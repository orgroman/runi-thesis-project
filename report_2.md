# Incorporating Logical Constraints in Dense Patent Retrieval

## Background: Dense Embeddings vs. Logical Constraints
Dense **embedding-based retrieval** represents text (queries and documents) as vectors in a semantic space. This enables efficient similarity search, but it struggles with **explicit logical conditions** (e.g. Boolean operators like NOT) embedded in natural language queries ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=Neural%20approaches%2C%20though%20more%20advanced,similarity%20score%2C%20such%20as%20cosine)). Traditional patent search by professionals relies heavily on Boolean logic – surveys show **Boolean operators are considered essential by ~96% of patent searchers** ([Proceedings Template - WORD](https://ciir-publications.cs.umass.edu/getpdf.php?id=974#:~:text=queries%20are%20particularly%20common%20in,In%20fact%2C%20a)). However, out-of-the-box neural models often fail to interpret negation or conjunction properly. For example, BERT-based encoders may treat words like “and” and “not” almost like synonyms, missing the **semantic difference introduced by negation** ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=Neural%20approaches%2C%20though%20more%20advanced,similarity%20score%2C%20such%20as%20cosine)). As a result, a query that includes an exclusion (e.g. *“X **not** Y”*) might still retrieve documents about **Y**, because the model finds them topically similar to *X* ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=benefits%20of%20vitamin%20D%2C%20focusing,exclusions%20or%20combinations%20of%20concepts)). This gap in understanding logical constraints leads to inaccurate results when performing **patent prior-art searches** that involve specific exclusions or combinations of concepts.

## Integrating Negation and Logic into Dense Representations
Researchers are exploring several strategies to incorporate **logical inference and negation** into dense retrieval methods. Notable approaches include:

- **Negation-Aware Model Training:** One line of work augments the training of dual-encoder models so they better handle logical operators. **SetBERT** (Mai *et al*., 2024) fine-tunes a BERT-based encoder on a synthetic query dataset with Boolean structures (AND, OR, NOT). It introduces an *“inversed-contrastive”* loss that focuses on pushing apart embeddings of queries and documents when a negation relationship exists ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=As%20stated%20earlier%2C%20our%20goal,contrastive%20loss%20becomes)). This helps the model learn that, say, *“A not B”* should be dissimilar to a document about *B*. SetBERT achieved up to a **63% improvement in recall** over a baseline BERT on queries with Boolean logic ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=negative%20sentence%2C%20and%20fine,third%20the%20size)). The model thus significantly improved retrieval for logic-structured queries – an area where both traditional and neural methods have underperformed ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=We%20introduce%20SetBERT%2C%20a%20fine,Our)). The key insight is to balance shared context vs. negated content: negation should push embeddings apart, but not ignore the common context entirely ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=However%2C%20this%20similarity%20is%20nuanced,tuning)).

- **Contrastive Learning for NOT:** Similarly, Cheng *et al*. (2024) constructed a benchmark called **BOOLQUESTIONS** with queries containing Boolean logic to evaluate dense retrievers ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=benchmark%20dataset%2C%20BOOLQUESTIONS%2C%20which%20in%02cludes,understand%20Boolean%20logic%20in%20language)). They found that **current dense models do not fully understand Boolean logic**, with especially large drops in performance on queries with **NOT** ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=finding%20significant%20performance%20drops%20on,the%20proposed%20baseline%20reduces%20the)). As a remedy, they generated additional *negation-heavy training data* and applied contrastive *continual learning* to better teach the model the concept of logical NOT ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=Based%20on%20these%20observations%2C%20we,in%20natural%20language%20for%20dense)). This approach reduced the incidence of irrelevant results (e.g. fewer false positives containing the excluded concept) ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=Based%20on%20these%20observations%2C%20we,in%20natural%20language%20for%20dense)). However, it came with a slight trade-off in overall accuracy, highlighting the difficulty of instilling a robust notion of negation in dense embeddings ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=a%20contrastive%20continual%20learning%20baseline,starting%20point%20for%20further%20research)). These efforts serve as early steps toward **negation-aware dense retrieval**.

- **Inference-Time Logical Reasoning:** Rather than baking logic into the embeddings themselves, another strategy is to perform **logical operations at query time** using the dense scores. Faltings *et al*. (2025) propose an inference-time framework for retrieval that explicitly **parses a natural language query into a logical form** (using an LLM) and then computes separate vector similarities for each component ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=Image%3A%20Refer%20to%20caption%20Figure,to%20generate%20the%20final%20results)) ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=to%20exclude%20documents%20related%20to,exclusions%20or%20combinations%20of%20concepts)). For example, the query *“benefits of vitamin D other than bone health”* is transformed into `Vitamin D Benefits AND NOT Bone Health` ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=Image%3A%20Refer%20to%20caption%20Figure,to%20generate%20the%20final%20results)). The system obtains embedding-based scores for “Vitamin D benefits” and for “bone health” and then **combines these scores according to the AND/NOT logic** to re-rank documents ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=Image%3A%20Refer%20to%20caption%20Figure,to%20generate%20the%20final%20results)). Essentially, documents get penalized if they are similar to the *excluded* term. This method doesn’t require retraining the encoder; it uses the existing embedding model but composes the similarity scores with logical operators (min/max or other functions reflecting AND, OR, NOT) ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=The%20choice%20of%20the%20operators,the%20following%20choices%20of%20operator)). Experiments showed that such **logical score composition** can significantly improve retrieval performance on complex queries, with the largest gains on queries involving negations ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=match%20at%20L221%20coming%20from,the%20appendix%20for%20a%20breakdown)) ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=negations%200%201%202%203,56)). In one evaluation, as the number of negation clauses in a query increased, a standard dense retriever’s effectiveness dropped sharply, whereas the logic-aware scoring maintained much higher accuracy ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=negations%200%201%202%203,56)). This **inference-time reasoning** approach is attractive for patent search because it can leverage mature embedding models (including domain-specific ones) and inject boolean reasoning when needed, without sacrificing efficiency ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=natural%20language%20queries%20and%20then,retrieval%20performance%20for%20complex%20queries)).

- **Geometric and Neuro-Symbolic Embeddings:** Another avenue is to change the representation space so that logical operations correspond to geometric operations. Research in knowledge graph embeddings, for instance, has represented queries as geometric regions (e.g. hyper-rectangles or cones) to naturally model set **intersection**, **union**, and **negation** ([[PDF] Faithful Embeddings for Knowledge Base Queries](https://proceedings.neurips.cc/paper/2020/file/fe74074593f21197b7b7be3c08678616-Paper.pdf#:~:text=,computation%20of%20an%20upper)). For example, **Query2Box** represents query terms as high-dimensional boxes, where an AND (intersection) is the overlap of boxes and a NOT could be a complementary region. Similarly, **GammaE** embeddings were designed to be closed under first-order logical operators (including negation) for query answering ([[PDF] Gamma Embeddings for Logical Queries on Knowledge Graphs](https://aclanthology.org/2022.emnlp-main.47.pdf#:~:text=,GammaE%20firstly)). While these techniques are developed for structured knowledge bases, the core ideas are adaptable: one could imagine dense text embeddings that encode concepts as regions or subspaces, where logical constraints filter or combine these regions. Early work on **“faithful embeddings”** for logical queries shows it’s possible to encode set difference (A minus B) in a vector space with specialized training ([[PDF] Faithful Embeddings for Knowledge Base Queries](https://proceedings.neurips.cc/paper/2020/file/fe74074593f21197b7b7be3c08678616-Paper.pdf#:~:text=,computation%20of%20an%20upper)). Adapting such methods to patent text (treating key concepts or attributes as embedding vectors) could allow **logical constraints (like exclusions)** to be modeled as vector operations. This remains a complex research area, but it underlines that a **neuro-symbolic approach** – blending neural embeddings with symbolic logic – is on the table for future patent retrieval systems.

- **Cross-Encoder Inference Models:** As an aside, using a cross-encoder (which reads the query and document together) can inherently capture complex logical relations, akin to doing **natural language inference (NLI)** between the query and document. For example, one can frame retrieval as an entailment problem: does the document **entail the query conditions** (and not contradict them)? Recent work on *entailment tuning* for dense passage retrieval seeks to align the embedding space with logical entailment ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=However%2C%20dense%20retrieval%20systems%20primarily,NOT%2C%20which%20exclude%20undesired%20information)) ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=Based%20on%20these%20observations%2C%20we,in%20natural%20language%20for%20dense)). In principle, a cross-encoder fine-tuned on entailment data will learn to give low scores if a document contradicts a query’s constraints (like containing a negated term that the query says “NOT”). This approach has been used to enhance dense retrievers by incorporating NLI objectives ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=finding%20significant%20performance%20drops%20on,the%20proposed%20baseline%20reduces%20the)). While cross-encoders are slower, they can be used in a reranking stage for high precision in patent search, ensuring that retrieved prior art truly meets the logical criteria of the query.

## Patent-Specific Challenges and Adaptations
**Patent prior-art queries** often involve highly specific technical criteria, sometimes expressed with logical constraints (e.g. *“a catalyst for reaction X **without** using mercury”*). Historically, patent examiners construct complex Boolean queries with multiple terms and exclusions to capture these requirements ([Proceedings Template - WORD](https://ciir-publications.cs.umass.edu/getpdf.php?id=974#:~:text=searches%20that%20are%20carried%20out,of)). Incorporating such logic into dense retrieval for patents has unique considerations:

- **Terminology and Domain Context:** Patent language is very precise. A negation like "without X" in a patent query is critical – retrieving a patent that does use X would be a failure. Dense models trained on general text may overlook the importance of “without” or “excluding” in the patent context. Adapting embeddings to patent text is crucial. Efforts like **BERT for Patents** (a BERT model pre-trained or fine-tuned on patent corpora) provide domain-specific embeddings that better capture technical semantics ([Microsoft Word - ICR24 paper - LLM-based Extraction of Contradictions from Patents - Stefan Trapp v0.2.docm](https://arxiv.org/pdf/2403.14258#:~:text=to%20go%20beyond%20keyword%02oriented%20methods,like%20language)). This improves overall relevance, but by itself doesn’t enforce logical constraints. Researchers are beginning to explore combining such **patent-specific language models** with the logic-aware techniques above. For instance, one could fine-tune a Patent-BERT model with the **inversed-contrastive loss** on generated patent queries that include negations or set operations, ensuring it learns to separate, say, *“polymer compositions with no halogens”* from those that have halogens.

- **Structured Fields and Metadata Filters:** Patent documents come with rich structure (claims, CPC classifications, etc.) that can be used to enforce constraints. A practical approach in patent retrieval systems is to perform **hybrid search**: use dense embedding similarity for semantic matching, but apply **Boolean filters** based on metadata or keyword occurrences. For example, a vector search for *“electric vehicle battery charging”* can be combined with a NOT filter to exclude documents classified under a certain category or containing a certain term (e.g., “exclude hybrid vehicles”). Modern search platforms like Vespa support such combinations by allowing a nearest-neighbor search clause to be combined with Boolean conditions in the query language ([Redefining Hybrid Search Possibilities with Vespa - part one](https://blog.vespa.ai/redefining-hybrid-search-possibilities-with-vespa/#:~:text=Redefining%20Hybrid%20Search%20Possibilities%20with,operators%20in%20the%20same)). While this doesn’t change the embeddings, it addresses negation at the system level. Many patent search tools (e.g., **PQAI**, an open-source patent search engine) incorporate this idea: use dense embeddings for recall, then apply logical rules or user-specified NOT clauses to refine results. This approach is effective in practice and can be seen as a form of **post-processing logical inference**.

- **Patent Claim Structure as Logical Context:** Some research leverages the structure of patent claims themselves to aid retrieval. A patent claim often enumerates features (sometimes with optional elements or exclusions). One technique is to **embed different parts of a patent separately** (e.g., each claim or each section) and then combine those embeddings when matching a query. For example, **Lin *et al*. (2019)** proposed a hybrid prior-art retrieval method that uses claim structure and descriptions ([Innovating Patent Retrieval: A Comprehensive Review of Techniques, Trends, and Challenges in Prior Art Searches](https://www.mdpi.com/2571-5577/7/5/91#:~:text=90.%20Lin%2C%20F.,In%20Proceedings%20of%20the%208th)). Although not explicitly about negation, such methods implicitly treat the presence or absence of certain elements as part of the similarity computation. By weighting key claim elements and down-weighting dissimilar parts, the system can ensure that if a query specifies a missing feature (“without X”), any candidate patent that explicitly includes X in a critical section is scored lower. This is akin to an **AND logic** across the set of claim conditions: each must be satisfied to some degree for a high overall similarity. Incorporating claim structure can thus preserve some logical relations in the embedding-based retrieval process.

- **Domain-Specific Negation Handling:** In the patent domain, negation might appear in specific linguistic forms (e.g., “devoid of”, “absent”, “lacking”). Effective retrieval may require recognizing these and ensuring the embedding reflects their effect. One possible adaptation is to enrich patent text embeddings with **knowledge graphs or ontologies** that encode opposites or exclusions. For instance, a knowledge graph could encode that a certain chemical being present is the logical negation of it being absent; a retrieval system could then adjust embeddings or scores if a query demands absence of a component. Preliminary work on **knowledge-augmented patent retrieval** uses external data (like inventor citations or technical taxonomies) to guide embeddings ([Enhancing patent retrieval using text and knowledge graph ...](https://www.tandfonline.com/doi/abs/10.1080/09544828.2022.2144714#:~:text=Enhancing%20patent%20retrieval%20using%20text,art%20techniques%20among%20natural)) ([Innovating Patent Retrieval: A Comprehensive Review of Techniques, Trends, and Challenges in Prior Art Searches](https://www.mdpi.com/2571-5577/7/5/91#:~:text=Knowledge%20Graph%20Embeddings%3A%20A%20Technical,Hawaii%20International%20Conference%20on%20System)). Though this work is more about adding semantic knowledge than formal logic, the added context can help a model distinguish, for example, *“non-metal catalyst”* from *“metal catalyst”* by understanding the category membership. In summary, **augmenting dense models with patent-specific lexicons for negation and contradiction** (perhaps via additional training signals or features) is an active area to ensure logical constraints aren’t lost in the semantic representation.

## Benchmarks and Datasets 
To evaluate and advance these methods, several **datasets and benchmarks** are used or newly created:

- **QUEST Dataset (Malaviya et al., 2023):** A retrieval benchmark of natural language queries that implicitly contain set operations (AND, OR, NOT) ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=The%20QUEST%20dataset%20The%20introduction,handle%20queries%20involving%20implicit%20set)). Each query maps to a set of Wikipedia entities as answers. QUEST challenges models to satisfy multiple constraints in the query and was influential in exposing how modern retrievers struggle, especially with **negation and conjunction** ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=influenced%20our%20work,handle%20queries%20involving%20implicit%20set)). For example, a query like *“writers from France and Italy in the 19th century”* requires an intersection of sets, while *“trees not found in the Amazon”* involves negation ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=Negation%20plays%20a%20critical%20role,trees%20and%20the%20Amazon%20region)). This dataset has been used to test approaches like SetBERT, which showed substantial gains on such queries ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=of%20QUEST%2C%20SetBERT%20represents%20a,art%20in%20IR)). Researchers interested in **logical retrieval** can use QUEST to measure how well their dense embedding models handle boolean logic in a general domain.

- **BOOLQUESTIONS Benchmark (2024):** Introduced in the context of the study on Boolean dense retrieval ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=benchmark%20dataset%2C%20BOOLQUESTIONS%2C%20which%20in%02cludes,understand%20Boolean%20logic%20in%20language)), this dataset consists of natural language queries with explicit Boolean operators (especially NOT) and corresponding relevant passages. It provides a focused way to evaluate **negation handling**. On BOOLQUESTIONS, standard dense retrievers (e.g., DPR, Sentence-BERT) see major drops in metrics for queries with “NOT” clauses, quantifying the problem ([](https://aclanthology.org/2024.findings-emnlp.156.pdf#:~:text=evaluate%20several%20state,While%20the%20proposed)). The dataset was used to demonstrate improvements from contrastive continual learning on negation, and it serves as a valuable resource for anyone trying new methods (the data and baseline code are often available via the authors’ repository or ACL anthology).

- **Patent Retrieval Benchmarks:** In the patent domain, large-scale test collections have been established through shared tasks:
  - The **CLEF-IP** evaluations (2009–2013) released millions of patent documents and query topics (typically a patent application for which prior art must be found) ([Innovating Patent Retrieval: A Comprehensive Review of Techniques, Trends, and Challenges in Prior Art Searches](https://www.mdpi.com/2571-5577/7/5/91#:~:text=language%20information%20retrieval%20%28CLIR%29.%20CLEF,data%20collection%20encompasses%20patent%20documents)). While these queries are documents rather than ad-hoc logical statements, CLEF-IP is useful for benchmarking neural retrieval models on patent prior art search. It highlights the difficulty of long documents and specific technical language ([[PDF] Retrieval for Extremely Long Queries and Documents with RPRS](https://arxiv.org/pdf/2303.01200#:~:text=,of%20documents%20in%20the)), but it doesn’t directly test negation handling since the queries aren’t Boolean expressions. That said, a system that can interpret a patent claim with exclusions (e.g. a claim that explicitly excludes a feature) as a query could be evaluated on CLEF-IP.
  - **NTCIR Patent Retrieval Tasks** (e.g., NTCIR-6) similarly provided test queries and relevance judgments for patent prior art search ([Innovating Patent Retrieval: A Comprehensive Review of Techniques, Trends, and Challenges in Prior Art Searches](https://www.mdpi.com/2571-5577/7/5/91#:~:text=Scholar%5D%20,of%20Patent%20Retrieval%20Task%20at)). These tasks often had English and Japanese patent queries. Again, the logical operators in queries were not explicitly tested, but the complex nature of patent text means a successful system must effectively handle concepts that *should* or *should not* appear in relevant results.
  - **PatentMatch (USPTO-Patent Matching Dataset):** A more recent dataset focused on matching patent **claims** to relevant **prior art paragraphs** ([PatentMatch: A Dataset for Matching Patent Claims & Prior Art - arXiv](https://arxiv.org/abs/2012.13919#:~:text=arXiv%20arxiv,and%20semantically%20corresponding%20text)). It contains thousands of claim–paragraph pairs labeled as matches. This can be seen as a retrieval task: for a given claim (which might contain negations or constraints in its language), find the prior art text that corresponds. PatentMatch is useful for training or evaluating dense models in understanding fine-grained semantic similarity in patents. While it doesn’t explicitly mark negations, many claims include phrases like “free of X” or “does not include Y,” so a model’s performance on PatentMatch can indicate how well it respects such constraints.
  - **IMPAct (NeurIPS 2024)** and other recent multimodal patent datasets include prior-art search components as well. These benchmarks are starting to combine text and images for patent retrieval. For our context, they emphasize that an ideal system might incorporate **multiple modalities and reasoning**. A query might be textual but exclude patents with a certain drawing or chemical formula, requiring logical filtering across modalities.

Notably, current patent-specific benchmarks do **not yet have a dedicated focus on negation queries**. There isn’t a public patent query set where topics like "find inventions doing X **but not** Y" are explicitly listed with ground-truth answers. This is a gap that future evaluations could fill. In the meantime, researchers often test negation handling by crafting their own query variations on existing data (for instance, take a CLEF-IP topic and add a NOT condition, then see if the system can exclude the relevant subset). The general-domain Boolean query datasets like QUEST and BOOLQUESTIONS are also being used as proxies to inspire methods that can be transferred to the patent domain.

## Tools and Implementations
Several implementations and libraries are emerging to support **logic-enhanced dense retrieval**:

- **SetBERT Code and Models:** The authors of *SetBERT* have released their fine-tuned model and, in some cases, training code (often via an academic GitHub or upon request). This model can be directly used as a drop-in replacement for a standard bi-encoder for queries that may involve logical operations. It produces a query embedding that better represents conjunctions and negations, which can then be used with any vector index. Using SetBERT for patent queries (especially after further fine-tuning on patent text) could immediately boost performance on complex queries ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=with%20triplet%20loss%20actually%20degrades,third%20the%20size)). *(If available, link to the SetBERT repository or HuggingFace model would be provided.)*

- **Logical Retrieval Frameworks:** The **inference-time logical reasoning** approach by Faltings et al. can be implemented on top of existing search infrastructure. In fact, it aligns well with how **vector databases** can operate: one can issue multiple embedding queries (for different sub-clauses) and then merge results. Although a specific open-source toolkit for this isn’t one-click, the method is described in their paper with pseudo-code ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=to%20exclude%20documents%20related%20to,exclusions%20or%20combinations%20of%20concepts)). It would not be surprising if this idea gets integrated into neural search platforms. For instance, **Vespa.ai** (Yahoo’s open-source search engine) allows writing queries that combine multiple similarity clauses with operators. A savvy user can reproduce “A AND NOT B” logic by querying for A’s embedding and subtracting scores for B’s embedding. Industry tools are heading in this direction, enabling **hybrid boolean–vector queries** out of the box ([Vespa nearest neighbor search - a practical guide](https://docs.vespa.ai/en/nearest-neighbor-search-guide.html#:~:text=This%20guide%20is%20a%20practical,with%20other%20Vespa%20query)).

- **Patent-Specific Embedding Models:** There are pre-trained models like **Patent-BERT** or **PatentSBERTa** available through the HuggingFace Transformers library. Google’s **BERT for Patents** model, for example, was trained on millions of patent sentences ([Microsoft Word - ICR24 paper - LLM-based Extraction of Contradictions from Patents - Stefan Trapp v0.2.docm](https://arxiv.org/pdf/2403.14258#:~:text=to%20go%20beyond%20keyword%02oriented%20methods,like%20language)) and is provided in the `google/patents-public-data` repository. These models can be used with libraries such as **Sentence-Transformers** to generate embeddings for patent texts. While these embeddings alone don’t solve the negation issue, they provide a strong semantic baseline tailored to patents. Integrating them with negation-aware training (via additional fine-tuning or contrastive learning as discussed) is feasible with open-source toolkits. There are also open datasets (like PatentMatch above) to fine-tune or evaluate these models on patent similarity tasks.

- **Patent Retrieval Platforms:** Projects like **PQAI** ([GitHub - mahesh-maan/awesome-patent-retrieval: Curated list of resources for processing patent data](https://github.com/mahesh-maan/awesome-patent-retrieval#:~:text=This%20is%20a%20curated%20list,databases%2C%20patent%20data%20sources%2C%20etc)) ([GitHub - mahesh-maan/awesome-patent-retrieval: Curated list of resources for processing patent data](https://github.com/mahesh-maan/awesome-patent-retrieval#:~:text=,80)) and **PatZilla** are open-source prior-art search engines that use AI methods. PQAI, for instance, uses dense vector search for patent paragraphs and claims, built on technologies like Elasticsearch/FAISS under the hood. These platforms often allow users to input natural language queries and will likely incorporate user-driven filters (e.g., a must-exclude keyword) – an opportunity to apply the logical re-scoring methods. Although not explicitly “negation-aware” at the embedding level, they are extensible. One could plug a SetBERT model into PQAI’s pipeline or add a reranking step to drop results that conflict with a negation in the query. The **PatentsView** and **Lens.org** APIs also provide semantic search over patents, and while their internal algorithms are not fully transparent, they could be using dual encoders with some post-processing. As interest grows, we expect to see community-contributed plugins for these tools to support boolean logic (for example, a **“MustNotContain”** filter on text fields in combination with vector similarity scoring).

- **Academic Libraries and Research Code:** Many of the papers cited provide code or at least detailed methodology. For example, the BOOLQUESTIONS authors might release their **contrastive continual learning** training script and the dataset. Using that, one can take any dense retriever (like HuggingFace’s `sentence-transformers` models for patents) and fine-tune it to better differentiate negated queries. Additionally, libraries like **pyserini** and **Haystack** – which facilitate building neural search systems – allow hybrid retrieval. Haystack, for instance, can use a dense retriever and then apply keyword filters to the results (emulating a NOT condition). Such frameworks are useful for rapid prototyping of negation-aware search: you can retrieve a batch with a dense model and then filter out any patent that contains the undesired term in its text or metadata.

In summary, while dense embedding techniques have revolutionized text similarity search, **enhancing them with logical constraints** is essential for high-accuracy patent prior-art retrieval. Research from both academia and industry is converging on solutions: from **specialized training losses for negation** ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=We%20introduce%20SetBERT%2C%20a%20fine,Our)) ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=As%20stated%20earlier%2C%20our%20goal,contrastive%20loss%20becomes)), to **inference algorithms that combine neural scores with Boolean logic** ([Enhancing Retrieval Systems with Inference-Time Logical Reasoning](https://arxiv.org/html/2503.17860v1#:~:text=to%20exclude%20documents%20related%20to,exclusions%20or%20combinations%20of%20concepts)). Key datasets like **QUEST** and **BOOLQUESTIONS** provide a way to measure progress on logical queries, and patent-specific resources like **CLEF-IP** and **PatentMatch** ensure these methods work in the real world of patent documents. Moving forward, practitioners can leverage these advances by incorporating **negation-aware models** and **logic-based re-ranking** into patent search systems, bridging the gap between intuitive Boolean querying and powerful semantic retrieval ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=Both%20traditional%20and%20neural%20retrieval,often%20returned%2C%20leading%20to%20inaccurate)) ([SetBERT: Enhancing Retrieval Performance for Boolean Logic and Set Operation Queries](https://arxiv.org/html/2406.17282v2#:~:text=Neural%20approaches%2C%20though%20more%20advanced,similarity%20score%2C%20such%20as%20cosine)). The result will be more accurate and trustworthy prior-art searches – for example, finding exactly those patents that meet all the inventive criteria *and* excluding those that violate any explicit constraints, a capability that is increasingly within reach of modern IR technology.
